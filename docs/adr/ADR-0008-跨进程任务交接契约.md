# ADR-0008 · 跨进程任务交接：四问的契约化

| 项 | 内容 |
|---|---|
| **状态** | 已采纳（Accepted） |
| **日期** | 2026-11-13 |
| **背景** | issue #110：`delegate` 只回答「能不能交给别的运行时」，`taskboard` 的认领只在**同一张板子内**。跨进程交接（进程 A 的一步工作移交给进程 B 续做）此前没有任何机制面：交接点在哪、交接是否原子、幂等键是什么、回执回到谁手里、交接超时怎么办——各宿主自己拿一个队列或一张表兜着，「双方都以为对方负责」与「谁都不负责」这两种错在报告里读起来完全正常。 |
| **决策** | 交接四问各收成一条契约条款（`handoff` 包）：① **交接点** = Store/Ticket——交接是把负责人字段改写一次，不是把任务推过管道；② **原子性** = 负责人转移发生在 `Take` 的一次原子操作里（存储保证、判据判结果：`ConcurrentTake` 赢家恰好 1）；③ **幂等键** = Ticket.Key 由调用方按业务给，同 Key 重复 `Offer` 是重放（返回原单），超时/收回后重新交接是新一代（Generation 与领取令牌同一次原子操作铸造）；④ **回执寻址** = `ReplyTo` 挂出时必填 + 只有 To 能领取 + 回执凭存储铸造的令牌；⑤ **超时** = 一条时限线覆盖领取与回执两段，截止时刻归存储按自己的时钟推算，无时限交接契约禁止，迟到的领取与回执一律拒收。 |
| **后果** | 新增内核契约包 `handoff`（契约 + 判据 `Validate` / `Check` / `ConcurrentTake` + 进程内参考实现 `LocalDesk`）；跨进程存储实现仍归宿主（与 taskboard「不给存储实现」同一分工，落库形态参考 examples/pgstore 先例）。代价：源方在时限内必须真的回来看（无时限交接不再可用）——这是「不留死锁」的价格，不是新的失真。 |
| **依据** | `handoff/handoff.go`（契约）、`handoff/judge.go`（判据）、`handoff/contention.go`（并发判据）、`handoff/local.go`（参考实现）、`handoff/handoff_test.go`（反向验证）；issue #110 第三轮清零 triage 切片。 |

> **一句话结论**：跨进程交接的契约不是队列，是**负责人字段的原子改写**——
> 交接点、幂等键、回执地址、时限四问各有一条可机械判定的答案。

---

## 缺口在哪儿

`delegate` 的回执是**同步调用**的回执：请求出去、结果回来，中间没有可以
崩溃的时间窗——它不需要回答「交接的时候谁负责」。

`taskboard` 的认领是**同一存储内**的认领：Claim 一次原子操作把 owner 字段
写掉，原子性由存储在**同一次事务**里给出。它不需要回答「交接发生在两个
进程之间怎么办」。

跨进程交接是两者的交集难题：**读-判-写三段分散在两个进程、两个时钟、
两条可能各自死掉的生命周期里**。各宿主自己兜的后果：

1. 「交接」被实现成**发消息**：消息发完源方就继续跑，接收方可能没收到、
   收到了可能没接——双方对「谁负责」各持己见，报告里只有两条各自成功。
2. 幂等键各造一套：重试路径要么重复施加（同键重开新单），要么静默丢失
   （同键判重判到别的东西上）。
3. 回执发到「谁交的回给谁」：源方崩溃重启后，回执发到已经不存在的身份上。
4. 没有时限：接收方死掉后交接单永久挂着，谁都不敢动它。

## 四问的答案（以及为什么不能少）

### 交接点：Store，不是管道

交接单是**数据**（Ticket），不是消息。消息会被吞、会重复、会乱序；
单据躺在 Store 里，领取之前它不会消失。判定「交接发生没有」变成读
单据状态，而不是猜消息去哪了。

### 原子性：Take 的一次操作，判据判结果

负责人转移必须发生在一次原子操作里——这是**存储实现**的义务，与
taskboard.Claim 同构。内核能给的是**判据**：`ConcurrentTake` 让 N 个
接收方同时抢，赢家必须恰好 1 个，输家必须是 `ErrTaken`。
把「存储连不上」算成输家，判据会在存储坏掉时变绿——它测到的是
「没有人赢」而不是「只有一个赢家」，两者都符合「winners <= 1」。

### 幂等键：调用方给，存储判

Key 由调用方按业务给（内核不造键——「什么算同一次交接」只有业务知道）。
同 Key 重复 `Offer` 是**重放**（返回原单，不开新单）——与 sideeffect 的
apply-once 同一条纪律。重新交接开**新一代**：Generation 同 Key 严格递增，
与领取令牌**同一次原子操作**铸造（taskboard v0.33.0 的教训：契约写着
「令牌由存储铸造」，实现却让调用方造，「凭令牌认人」就名存实亡）。

### 回执寻址：显式 ReplyTo + 领取验身份

`ReplyTo` 挂出时必填。回执送到**源方显式声明的地址**，不假设「谁交的
回给谁」——跨进程时源方可能崩溃重启，重启后的身份不一定还是交接时的
身份。领取只允许 To 本人（`ErrNotAddressee`）；回执凭存储铸造的令牌提交
（`ErrLeaseLost`）——凭令牌认人，不凭内容，commitgate / taskboard 的
同源教训。

### 超时：一条时限线，两段共用

`TTL` 覆盖领取与回执两段，截止时刻由存储按**自己的**时钟推算（给
「多长」不给「到什么时候」——跨进程不假设时钟一致，taskboard.ClaimRequest
的同源纪律）。到点未领取或已领取未回执，单落 expired：迟到的领取与回执
一律拒收（fail-closed），重新交接即新一代。**无时限的交接是契约禁止的**
（Validate 拒绝 TTL<=0）。

## 为什么实现放进程内、落库归宿主

`LocalDesk` 只证**契约可满足**（判据跑在它身上、过期语义可确定性测），
它对跨进程不做任何承诺——原子性由进程内互斥给出，崩溃语义没有落库背书。
跨进程落库形态归宿主，参考 examples/pgstore 对 taskboard.Board 的分工：
内核证契约，示例证接线。给一份跨进程参考实现，宿主就会照着改它，
最后两份真相并存。

## 边界（刻意不做的）

- **不定义传输**：交接单怎么到达接收方的视野（轮询 / 推送 / 订阅）是
  宿主的部署形态，契约只保证「单据在 Store 里」这一事实可判定。
- **不定义回执投递**：`ReplyTo` 是地址不是通道——把回执送到地址是
  宿主的活，契约只要求「地址必须有人声明过」。
- **不拆两段时限**：领取与回执共用一条线是本轮的刻意简化；两段独立
  时限（领取窗 + 回执租约）留给真实宿主磨合后再拆，拆的时候 Handle.Until
  与 Ticket.Deadline 分叉即可，接口不用破坏。
